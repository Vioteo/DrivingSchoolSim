# Город: тестовый район из модулей

Статус: **проект** (24.09.2026). Ничего из описанного ниже ещё не реализовано. Решения: [ADR-011](adr.md#adr-011--район-собирается-из-модулей-с-семантикой-граф-компилируется-из-раскладки), [ADR-012](adr.md#adr-012--ии-трафик-кинематический-в-координатах-полосы-s-d), [ADR-013](adr.md#adr-013--таблица-ошибок-экзамена-как-версионированные-данные). Карточки: T27–T39 (см. [индекс](tasks/README.md)).

Цель первого района — не красота, а **проверяемая связка**: модули → граф → сцена → ИИ-трафик и пешеходы → правила ПДД и баллы экзамена. Плотность для первых тестов низкая.

## Конвейер сборки

```
RoadKit (Blender) ──► FBX + префабы (RoadKitBuilder)
       │
       └─► шаблоны семантики модулей (T28, JSON рядом с catalog.json)
                        │
раскладка района (T29, JSON) ──► компилятор (pure C#) ──► WorldDocument v2 (T11 + T27)
                                                                   │
                               ┌───────────────────────────────────┤
                               ▼                                   ▼
                 сцена/коллайдеры (T30)          ДИСПЕТЧЕР ТРАФИКА (T35, ADR-014)
                                                 ├─ реестр участников (ИИ, пешеходы, игрок)
                                                 ├─ привязка к графу (T31)
                                                 ├─ светофоры (T32)
                                                 ├─ резервы перекрёстков и переходов (T33)
                                                 ├─ появление/исчезновение, уровни детализации
                                                 └─ вызывает поведение: T16, T34, T17/T36
                                                                   │ снимок состояния на тик
                                  ┌────────────────────────────────┼──────────────────────┐
                                  ▼                                ▼                      ▼
                    представление (машины, пешеходы,     правила (T18, T37)     отладка (T38)
                    светофоры в сцене)
```

Правила:
- Граф — единственный источник истины. Ни ИИ, ни правила не читают меши и не ищут объекты сцены по имени.
- Сцену района не правят руками: меняют раскладку или генератор (CLAUDE.md, правило 2).
- Компилятор — чистый C# (`DS.World` или новый pure-модуль по решению в T29), поэтому раскладка тестируется без Unity.

## Что добавляется в граф v2 (сверх T11)

T11 даёт кривые, полосы с осевыми линиями, `LaneConnection` с конфликтными группами, стоп-линии, переходы и привязку светофоров. Для города нужно ещё (T27):

| Данные | Зачем |
|---|---|
| Тип разметки между соседними полосами и по оси (сплошная / прерывистая / двойная / отсутствует), с участками по `s` | перестроение и объезд ИИ; правило «пересёк сплошную» |
| Разрешённые манёвры полосы (прямо / направо / налево / разворот) | выбор полосы ИИ; правило «поворот не из той полосы» |
| Знаки как данные: код по ГОСТ Р 52290-2004, полосы, к которым относятся, начало и конец зоны действия | скоростной режим, запреты, приоритет |
| Приоритет въезда на перекрёсток: главная / второстепенная / равнозначная / регулируемый | правила проезда для ИИ и игрока |
| Сеть тротуаров: полилинии, связи, привязка переходов к пересекаемым полосам | навигация пешеходов |
| Зоны: парковка, остановка запрещена, стоянка запрещена, «не выезжать на перекрёсток при заторе» | упражнения экзамена, поведение ИИ в пробке |
| Точки появления и исчезновения агентов | диспетчер трафика |

Знаки в сцене ставятся **из графа**, а не отдельно, поэтому их положение не может разойтись с правилами. Размещение знаков проверяется по ГОСТ Р 52289-2019. Редакцию и пункт исполнитель записывает при реализации проверки; нормы не выдумываются (CLAUDE.md, правило 5).

## Шаблон модуля

Каждый модуль RK_* получает файл семантики (T28), в локальных координатах префаба (Unity, X вправо, Z вперёд, метры):
- стыки (`Socket_*`): положение, направление, профиль (число полос в каждую сторону, ширина полосы, тротуары);
- полосы и связи внутри модуля с осевыми линиями и зонами конфликта;
- стоп-линии, переходы, тротуары и места под знаки и светофоры — в тех же координатах, что и в меше.

Координаты берутся из `tools/build_road_kit.py`, не подбираются на глаз. Генератор района (T30) проверяет, что разметка шаблона совпадает с разметкой меша (допуск 5 см).

## Тестовый район

### Геометрия текущего набора
Сейчас есть прямая 20 м (1+1, проезжая часть 8 м), поворот 90° R14 и крестовой перекрёсток 24 м (входы на ±12 м). Если модули стыкуются только по сокетам, **замкнутая сеть кварталов не собирается**:
- расстояние между центрами соседних перекрёстков: `L = 24 + 20·m`;
- объезд по внешней петле (два поворота R14 и прямые): `L = 28 + 20·k`.

Разница всегда 4 м. Нужны короткие прямые (минимум 2, 4, 5 и 10 м) и Т-образный перекрёсток — это T39. До неё район собрать нельзя, только одиночные перекрёстки.

### Состав
**v0: только 1+1, после T39 (короткие прямые, Т-перекрёсток):** сетка 3 × 3 узла, шаг около 124 м, район примерно 300 × 300 м.
- 4 угловых поворота, 4 Т-перекрёстка по краям, 1 центральный крест.
- Центр — регулируемый перекрёсток (светофор, пешеходные светофоры).
- Т-перекрёстки: два «главная / второстепенная» (2.1 / 2.4 или 2.5), один равнозначный, один со вторым регулируемым переходом.
- Между узлами: нерегулируемый пешеходный переход (5.19.1/5.19.2) и зона 3.24 «40»; парковочный карман.
- Перестроений нет (одна полоса в каждую сторону). Объезд — только через встречную, где разметка прерывистая.

**v1: добавить проспект 2+2 после T39 (модули 2+2, переход 1+1 → 2+2, крест 2+2 × 1+1):** проспект через центр с регулируемым перекрёстком и дополнительной секцией направо. Здесь проверяются перестроение, выбор полосы под манёвр и заторы.

Кольцо, железнодорожный переезд (ассет есть, см. `railway-crossing.md`) и дворы — позже, отдельными модулями.

## Привязка участника к графу

Сервис T31 для любого участника (игрок, ИИ, пешеход) по позе выдаёт полосу, `s`, `d`, связь на перекрёстке, по которой он едет, и действующие знаки и зоны. Учитывается гистерезис, чтобы на границе полос полоса не «прыгала». От этого сервиса зависят:
- правила: какая полоса, какой знак действует, был ли манёвр — поворот определяется по графу, а не по углу руля;
- ИИ: видит игрока как обычного участника на полосе.

## Диспетчер трафика

Решение — [ADR-014](adr.md#adr-014--единый-диспетчер-трафика). Один узел `TrafficDirector` (pure C#) управляет всем движением района; в Unity его обслуживает один `TrafficDirectorHost`. Никакой другой MonoBehaviour не принимает решений о движении.

### Что делает диспетчер за один тик
1. Получает позу и состояние машины игрока от адаптера физики, привязывает её к графу (T31).
2. Тикает все светофоры района (T32).
3. Строит **один неизменяемый снимок**: участники в координатах полос, сигналы, занятые зоны и переходы.
4. Для каждого агента вызывает модули поведения (T16, T34, T17) с этим снимком. Агенты принимают решения независимо от порядка обхода.
5. Рассматривает запросы агентов на манёвры, выдаёт разрешения или отказы и рассылает уведомления затронутым участникам (см. «Разрешения и уведомления» ниже, T40). Въезд в зоны конфликта и на переходы — частный случай такого запроса (T33). Если два агента претендуют на одно, решает диспетчер: по сигналу, по приоритету, по правилу разрешения блокировки. Игроку разрешений не выдают — он едет как хочет, а ИИ уступает ему по правилам и ради безопасности.
6. Продвигает кинематику агентов.
7. Появление и исчезновение агентов, переключение уровней детализации.
8. Публикует снимок: представление расставляет машины, пешеходов и сигналы, правила ПДД оценивают игрока по тому же снимку, отладка показывает решения.

Шаг решений — 10 Гц, кинематика — каждый тик симуляции, в представлении интерполяция. Пауза останавливает диспетчер целиком. Одинаковый seed и одинаковый ввод игрока дают одинаковую историю.

### Появление, исчезновение и уровни детализации
- **Ближняя зона** (примерно до 250 м от игрока, только в загруженных чанках): полное поведение, коллайдеры, отображение.
- **Фоновая зона** (дальше, в пределах района или города): упрощённое движение по маршруту (только IDM, без перестроений), 1–2 Гц, без объектов в сцене. Нужна, чтобы машины подъезжали к игроку из уже существующего потока, а не появлялись из ниоткуда.
- **Дальше** агентов нет, плотность поддерживается появлением на границе фоновой зоны.
- Агенты появляются и исчезают только вне поля зрения игрока и только в загруженных чанках (связь с T12 — событие «чанк готов»). При выгрузке чанка агенты в нём переходят в фоновую зону или удаляются.
- Светофоры вне загруженной области не тикают: их фаза вычисляется из плана по времени, поэтому при загрузке сигнал сразу в правильной фазе.
- Плотность задаётся в данных. **Первые тесты: до 8 машин и до 10 пешеходов на весь район.** Для района v0 (300 × 300 м) почти всё находится в ближней зоне; уровни детализации нужны уже для города.

### Разрешения и уведомления
Решение — [ADR-015](adr.md#adr-015--манёвры-ии-через-разрешение-диспетчера-с-уведомлением-участников). Манёвр, который затрагивает других, агент не начинает сам: **запрос → разрешение на время → уведомление затронутых**.

| Запрос агента | Что проверяет диспетчер | Кого и о чём предупреждает |
|---|---|---|
| Въезд в зону конфликта перекрёстка (T33) | сигнал, приоритет, свободна ли зона, есть ли место за перекрёстком | машины на конфликтующих связях: «жди, зона занята до t» |
| Перестроение в соседнюю полосу (T34) | окно в целевой полосе, сплошная ли разметка, торможение заднего соседа не сильнее порога | задний сосед в целевой полосе: «открой окно» (плавное снижение скорости); передний: «не тормози резко без причины» |
| Обязательное перестроение перед поворотом | то же, с повышенной срочностью | как выше; если окна нет — разрешение «остановиться и ждать с поворотником» |
| Поочерёдное слияние при сужении | порядок очереди на слияние | машины продолжающейся полосы: «пропусти одну» |
| Объезд через встречную (T34) | свободный участок встречной на длину манёвра с запасом по TTC | встречные на участке: «снизь скорость», попутные сзади: «не начинай обгон» |
| Выезд с парковки или из двора | окно в потоке | подъезжающие по полосе: «открой окно» или отказ, если окна нет |
| Переход дороги пешеходом (T36) | сигнал пешеходного светофора или TTC приближающихся машин | машины перед переходом: «уступи пешеходу», переход занят до t |
| Остановка с аварийкой, заглохшая машина, ДТП | — (не запрос, а сообщение) | машины выше по потоку: «препятствие на полосе в s», чтобы они заранее перестроились или начали объезд |

Правила протокола:
- Разрешение действует ограниченное время. Не успел — разрешение снимается, агент выполняет запасной вариант (вернуться в полосу, остановиться), соседи получают «отбой».
- Уведомления применяются на следующем тике, один раз для всех, поэтому порядок обхода агентов не важен.
- Уведомлённая машина реагирует только на видимые признаки: запрос на перестроение подаётся вместе с включением поворотника, и сосед начинает открывать окно не раньше, чем поворотник горит заданное время. Иначе трафик будет выглядеть «телепатическим», а ученик не научится читать сигналы других машин.
- Профиль водителя задаёт, насколько охотно машина пропускает (вежливый, обычный, торопливый), но не позволяет нарушить безопасность.
- **Игрок** запросов не подаёт. Диспетчер оценивает его намерение по поворотникам и траектории и создаёт «наблюдаемую заявку»: ИИ её учитывает. Если игрок перестраивается без поворотника, ИИ реагирует только когда машина уже смещается в его полосу — как в жизни, и это же становится нарушением для правил.
- Каждое разрешение, отказ и уведомление есть в снимке — отладочный слой (T38) показывает, кто кому что разрешил и почему.

### Столкновения
Машина ИИ — kinematic Rigidbody с коллайдером. При контакте с игроком адаптер сообщает диспетчеру, тот останавливает агента, включает ему аварийку и публикует событие для правил. Агент не «таранит» игрока и не проходит сквозь него.

## ИИ-трафик

Модель — [ADR-012](adr.md#adr-012--ии-трафик-кинематический-в-координатах-полосы-s-d). Агент хранит `(laneId, s, d, v, a)` и маршрут — список связей полос (A* по графу). В Unity агент — kinematic Rigidbody: позу считает симуляция, адаптер только ставит её. Колёса и кузов — визуальные: поворот колёс по кривизне, крен по боковому ускорению.

### Продольное движение и заторы (T16)
- IDM: желаемая скорость = min(лимит полосы с учётом знаков, профиль водителя), минимальный зазор `s0` около 2 м в заторе, интервал `T` 1–1,5 с. Все значения — игровые параметры в данных.
- Плавное трогание в пробке: задержка реакции 0,3–1 с по профилю водителя, чтобы колонна не трогалась одновременно.
- «Не выезжать на перекрёсток при заторе»: перед въездом в зону конфликта агент проверяет, что за перекрёстком по его маршруту есть место на длину машины и зазор (ПДД РФ, п. 13.2 — редакцию сверить).
- Стоп-линия, красный, жёлтый: остановка, если можно остановиться с замедлением не больше заданного; иначе проезд.

### Перестроение (T34)
- Поперечное смещение `d(t)` — полином пятой степени за 2–4 с в зависимости от скорости. Пока идёт перестроение, агент **занимает обе полосы**, и соседи видят его в обеих. На середине полоса агента меняется, `d` пересчитывается.
- Решение по MOBIL: выгода для себя, «вежливость» к заднему соседу, порог безопасного торможения нового заднего соседа.
- Обязательные перестроения под маршрут (поворот, окончание полосы): срочность растёт по мере приближения к точке, где надо быть в полосе. Если перестроиться не удалось — остановка с поворотником и ожидание окна, а в крайнем случае перестроение маршрута. Задом ИИ не сдаёт.
- Слияние при сужении — поочерёдно («молния»): агент в продолжающейся полосе оставляет окно одной машине.
- Разметка из графа: через сплошную не перестраивается никогда.
- Поворотник включается за 2–3 с до начала манёвра и гаснет после него. Стоп-сигналы — по замедлению. Это нужно игроку, чтобы понимать намерения ИИ.

### Объезд препятствия (T34)
Препятствием считается любой участник или объект, который стоит на полосе дольше порога: стоящая машина, заглохший игрок, машина с аварийкой, ДТП.
1. Если препятствие занимает полосу частично и по свободной части проходит машина с запасом — смещение `d` внутри полосы на пониженной скорости.
2. Если есть соседняя попутная полоса — перестроение по MOBIL с повышенной срочностью.
3. Если соседняя полоса только встречная и разметка прерывистая — объезд через встречную. Условие: свободная встречная на длине манёвра с запасом по TTC. Решение принимается один раз, отказ от манёвра на середине не допускается. Как это соотносится с пунктами ПДД о выезде на встречную, фиксируется в T34 со ссылкой и редакцией.
4. Иначе — ожидание. Если маршрут это позволяет, через время ожидания агент меняет маршрут.

### Перекрёстки (T33)
- Каждая связь полос на перекрёстке пересекает другие в известных зонах конфликта (из графа). Агент **запрашивает** зону на время проезда с запасом, таблицу резервов ведёт диспетчер: одну зону не могут получить два агента.
- Порядок приоритета: сигнал светофора → знаки приоритета → помеха справа на равнозначном → уступить встречным при повороте налево → уступить пешеходам на переходе, куда поворачиваешь. Пункты ПДД (6.2, 13.4, 13.9, 13.11, 14.1 и др.) указываются в данных связей с редакцией.
- Защита от взаимной блокировки (четыре машины на равнозначном): граф ожиданий; если в нём цикл дольше порога, проезжает агент с наименьшим id. Это игровое правило, в документации оно помечено как игровое.

## Пешеходы (T17, T36)
- Движение по полилиниям тротуаров с тем же принципом `(s, d)`: смещение для обгона и встречного расхождения, простое расталкивание.
- Переход — фазы из T17 (ждёт у бордюра → оценивает разрыв или сигнал → идёт → вышел на тротуар). Переход занят для ИИ и правил, пока на нём пешеход.
- Анимация: в риге есть только клипы Idle и Walk. Нужен Animator со скоростью шага, привязанной к фактической скорости, иначе ноги «скользят».
- Учебные сценарии («выходит из-за стоящего автобуса») — отдельная карточка позже, не в v0.

## Правила и баллы экзамена
- Таблица ошибок — данные по [ADR-013](adr.md#adr-013--таблица-ошибок-экзамена-как-версионированные-данные): приказ МВД № 80, Приложение 5, последняя доступная редакция (на 24.09.2026 — от 26.05.2025). Перенос — T37.
- Правила подключаются по одному семейству за карточку (T18). Порядок для района: скорость по знакам и зонам → стоп-линия и сигнал светофора → поворотник перед манёвром (по графу) → сплошная разметка → проезд перекрёстков и уступить дорогу → пешеходный переход.
- Поворотник, свет и ремень невозможно проверить, пока в `DriverCommand` нет этих команд (аудит, приоритет 2). Это зависимость, а не часть городских карточек.

## Отладка и проверка (T38)
- Отладочный слой в Play Mode: полосы и связи, зоны конфликта и их резервирование, фазы светофоров, для каждого агента — текущее решение («жду помеху справа», «перестраиваюсь», «объезжаю»). Без него качество ИИ не отладить.
- Сценарные тесты без графики на графе района: «уступил помехе справа», «остановился на красный», «не выехал на перекрёсток при заторе», «объехал стоящую машину через прерывистую», «не перестроился через сплошную», «пешеход не вышел при TTC 2 с». У каждого сценария есть отрицательный вариант, и тест сначала падает на неверном входе.

## Порядок работ
1. T11 → T27: граф v2 и его городская часть.
2. T39 (арт, параллельно): короткие прямые, Т-перекрёсток, затем модули 2+2.
3. T28 → T29 → T30: шаблоны модулей, раскладка и компилятор, генератор района v0.
4. T31 (привязка), T32 (светофоры), T16 (движение по полосе).
5. T35 — каркас диспетчера: реестр, порядок тика, светофоры, появление и исчезновение машин с T16, Unity-хост. С этого момента в районе ездят машины.
6. T40 → T33 → T34: протокол разрешений и уведомлений в диспетчере, затем перекрёстки, перестроение и объезд — как запросы этого протокола.
7. T17 → T36: пешеходы регистрируются в диспетчере.
8. T37 → T18 и следующие семейства правил — читают снимок диспетчера.
9. T38 сопровождает шаги 4–8: каждый новый ИИ-сценарий получает тест и отображение в отладке.
