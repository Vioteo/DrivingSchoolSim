# Модели: создание, экспорт и импорт в Unity

Единый стандарт для людей и агентов. Составлен 23.09.2026 по фактическому состоянию `tools/*.py`, `Code/Editor/*Builder.cs` и документов по наборам (`road-kit.md`, `traffic-assets.md`, `ArtSource/Houses/README.md`, `asset-standard.md`, `model-iteration.md`).

Там, где разные наборы делают по-разному, **этот документ главный**. Устаревшие отличия перечислены в разделе 10 и исправляются отдельными задачами.

## 0. Конвейер одной модели

```
tools/build_<kit>.py  →  ArtSource/<Kit>.blend  →  Assets/DrivingSchool/Art/<Kit>/*.fbx   (+ GLB для просмотра)
   (скрипт Blender)        (исходник)               (экспорт для Unity)

Code/Editor/<Kit>Builder.cs  →  Prefabs/<Kit>/*.prefab  →  проверка  →  отчёт в artifacts/
   (настройки импорта,          (корень-обёртка,                 (размеры, оси,
    коллайдеры, LOD)             дочерний Model)                  рендеры ДО/ПОСЛЕ)
```

Главное правило: **модель создаётся и меняется воспроизводимым Python-скриптом Blender**, а не ручными правками в интерфейсе. Скрипт — источник истины, `.blend` — его результат, FBX — экспорт. Если модель правили руками в Blender, правка фиксируется новой ревизией исходника (раздел 2), и скрипт поверх неё больше не запускают.

## 1. Инструменты
- Blender 5.0: `C:\Program Files\Blender Foundation\Blender 5.0\blender.exe`, только пакетный режим: `blender -b [файл.blend] --python tools/<script>.py`.
- Unity 6000.3.10f1: `E:\unityroot\6000.3.10f1\Editor\Unity.exe`, пакетный импорт: `-batchmode -projectPath . -executeMethod DrivingSchool.Editor.<Kit>Builder.Build -quit -logFile artifacts/reports/<kit>-unity.log`. Editor этого проекта перед запуском закрыть.
- Скриншоты из Unity: метод `Capture` без `-nographics`.

## 2. Файлы, имена, версии
| Что | Где | Имя |
|---|---|---|
| Скрипт генерации | `tools/` | `build_<kit>.py`, проверка — `verify_<kit>.py` |
| Исходник | `ArtSource/` (или `ArtSource/<Kit>/`) | `DS_<Name>.blend`; наборы: `DS_<Kit>Kit.blend` |
| Экспорт для Unity | `Assets/DrivingSchool/Art/<Kit>/` | как объект: `DS_*`, `RK_*` (дороги), `TK_*` (площадка) |
| Текстуры | `Assets/DrivingSchool/Art/<Kit>/Textures/` | `<Prefix>_<Material>.png` |
| Материалы | `Assets/DrivingSchool/Materials/<Kit>/` | общие на набор |
| Префабы | `Assets/DrivingSchool/Prefabs/<Kit>/` | как FBX |
| GLB, рендеры, страница проверки | `artifacts/visual-review/<kit>/` | — |
| Машинный отчёт (manifest) | `artifacts/reports/<kit>-manifest.json` | SHA256, размеры, треугольники, материалы |

- Префиксы: `DS_` — общие ассеты проекта, `RK_` — дорожный набор, `TK_` — учебная площадка, `PT_` — общественный транспорт, трамвайные пути и остановки (`docs/transit-kit.md`). Новый набор получает свой двухбуквенный префикс, его записывают в этот документ.
- Имена: латиница, `PascalCase_С_Подчёркиваниями`, **без пробелов**. Единицы в имени пишутся как `20m`, `3p5m` (3,5 м), `R14` (радиус).
- **Версии хранит git, а не имя файла.** Новые `_v1`, `_reviewed`, `_final` не создаются. Если нужны два варианта одновременно (например, закрытый и открытый кузов), это разные ассеты с осмысленными именами.
- `*.blend1` (автобэкапы Blender) не хранятся: добавить в `.gitignore`.
- GLB нужен только для веб-просмотра. В `Assets/` его не кладут.

## 3. Моделирование в Blender
- Единицы: Metric, Unit Scale **1.0**, 1 BU = 1 м. Реальные размеры, без масштабирования «на глаз».
- Оси Blender: **Z вверх, лицевая сторона смотрит в −Y**. После экспорта это даёт Y вверх и лицо в +Z в Unity. У автомобиля перёд тоже в −Y.
- Перед экспортом у всех объектов применены трансформации (Apply All Transforms): scale = 1, rotation = 0. Исключение — пустышки-пивоты подвижных частей: их ориентация и есть ось вращения.
- Точки привязки (origin) корня:
  - знаки, светофоры, столбы, дома, конусы — центр основания на земле (Y = 0);
  - дорожные модули — начало участка, `Socket_Start` в (0,0,0), `Socket_End` в конце;
  - автомобиль — середина между пятнами контакта колёс на земле, по центру ширины;
  - таблички — середина нижней кромки.
- Нормали наружу, без инвертированных граней, без z-fighting и висящих деталей. Намеренные щели помечаются в отчёте.
- Модификаторы применяются при экспорте. Исходник хранит их неприменёнными, если скрипт так строит.
- Кириллица на знаках — mesh из текста (как в `build_traffic_assets.py`), без внешних шрифтов.
- Графика знаков, разметки и светофоров стилизована, но **габариты и цвета — по ГОСТ Р 52290 / 52289 / 51256**, если модель претендует на нормативность. Иначе в документе набора пишем «стилизовано».

### Имена объектов внутри модели
| Префикс или имя | Смысл | Что делает импортёр |
|---|---|---|
| `COL_*` | упрощённая коллизия | MeshCollider/BoxCollider, рендер выключен |
| `DriveSurface*` | поверхность, по которой едет автомобиль | слой `DriveSurface` (9), MeshCollider |
| `*_LOD0`, `*_LOD1`, `*_LOD2` | уровни детализации | LODGroup |
| `Socket_*` | точки привязки (DriverEye, CentreOfMass, Start, End…) | пустышка, не рендерится |
| `*_Pivot`, `Wheel_FL/FR/RL/RR` | подвижные узлы, ось = локальная ось пустышки | анимируется кодом по имени |
| `Needle_*`, `Wiper_Pivot_*` | стрелки приборов, дворники | поиск по префиксу |
| `Pedal_Throttle/Brake/Clutch`, `SteeringWheel_Pivot` | органы управления | по имени |
| `MirrorSurface_L/R/Centre` | поверхности зеркал | слой `Mirror` (8), компонент `PlanarMirror` |
| `Lamp_Red/Amber/White…`, `Headlight`, `Taillight`, `Brake` | светящиеся элементы | включаются кодом (TrafficSignalView, свет авто) |

Полный список обязательных имён автомобиля — в `asset-standard.md`, раздел «Совместимость имён». **Переименовывать эти объекты нельзя** без правки кода, который их ищет. Декоративные объекты не должны случайно начинаться с этих префиксов.

## 4. Экспорт FBX (обязательные параметры)
```python
bpy.ops.export_scene.fbx(
    filepath=..., use_selection=True,
    object_types={'MESH', 'EMPTY'},        # + 'ARMATURE' для пешеходов
    axis_forward='-Z', axis_up='Y',
    apply_unit_scale=True, apply_scale_options='FBX_SCALE_UNITS',
    add_leaf_bones=False, bake_anim=False)  # bake_anim=True только для анимированных
```
- Один FBX = один ассет (один будущий префаб). Карты и площадки целиком в один FBX не собираются: они строятся в Unity из модулей генератором сцены.
- После экспорта скрипт пишет manifest (SHA256 исходника и FBX, габариты, треугольники по LOD, число материалов) и делает повторный импорт в Blender для сверки размеров.

## 5. Импорт в Unity
Каждый набор импортирует свой `Code/Editor/<Kit>Builder.cs` (меню **Driving School → <Kit> → Build…**). Ручные настройки в Inspector не делаются: при следующей сборке они перезапишутся.

Обязательные настройки `ModelImporter`:
```csharp
importer.globalScale = 1; importer.useFileScale = true;
importer.bakeAxisConversion = true;           // корень без поворота −90°
importer.importCameras = false; importer.importLights = false;
importer.importAnimation = false;             // true + Generic только для анимированных (пешеходы)
importer.materialImportMode = ModelImporterMaterialImportMode.ImportStandard;
importer.isReadable = false;                  // true только если меш читают в рантайме
importer.generateSecondaryUV = true;          // для статики под lightmap
```
Структура префаба:
```
DS_Sign_Stop            ← корень: identity transform, scale 1, компоненты (коллайдеры, скрипты)
 └─ Model               ← экземпляр FBX; повороты не трогать
     └─ COL_* (выкл. рендер), *_LOD0..2, Socket_* …
```
- Builder обязательно проверяет габариты и оси после импорта (как `HouseKitBuilder`) и падает с ошибкой, если модель лежит на боку или масштаб не в метрах.
- Builder изменяет только свои префабы, материалы и демо-сцену. Общие сцены и список сцен сборки он не трогает.

## 6. Слои и коллизии
Слои задать именами в **Project Settings → Tags and Layers** (сейчас в коде используются номера без имён):

| № | Имя | Что |
|---|---|---|
| 8 | `Mirror` | поверхности зеркал |
| 9 | `DriveSurface` | дорога, эстакада — по ним raycast колёс |
| 10 | `SolidProp` | конусы, ограждения, столбы, здания — препятствия |
| 11 | `PlayerVehicle` | автомобиль игрока |

В коде обращаться к слоям через `LayerMask.NameToLayer`/константы, а не через `1<<9`.

Правила коллизий:
- Коллизия берётся из `COL_*` в модели или задаётся примитивом в Builder (Box/Capsule). Визуальный меш с сотнями деталей коллайдером не делается.
- Дорожные поверхности: статический MeshCollider. Разметка без коллайдера.
- Столбы и стойки: Capsule. Щиты и корпуса: Box.
- Движущиеся объекты (автомобиль, трафик): только выпуклые (convex) коллайдеры или примитивы.

## 7. Материалы и текстуры
- Шейдер URP/Lit (или Shader Graph из `Materials/`). Цвета — из `Art/palette.json`, чтобы стиль был единым.
- Материалы общие на набор, в `Materials/<Kit>/`. Одинаковые материалы в каждом FBX не создаются.
- Текстуры: фон и пропсы 512–1K, дорожные бесшовные 512–1K, кузов до 2K, приборы до 4K по читаемости. PNG, sRGB для цвета, Linear для масок и нормалей.
- Светящиеся элементы — отдельный материал с Emission, чтобы код мог его включать.

## 8. Бюджеты
Бюджеты по треугольникам, LOD и материалам — в `asset-standard.md`, раздел «Окружение и целевые бюджеты». Кратко: автомобиль игрока — кузов LOD0 ≤ 80k, салон ≤ 60k треугольников, ≤ 12 материалов; машина трафика LOD0 ≤ 35k; у массовых объектов (дома, знаки, деревья) обязательны LOD. Новые наборы без LOD помечаются «LOD не подготовлены».

## 9. Приёмка ассета (чек-лист)
1. Скрипт запускается с нуля в `-b` и воспроизводит `.blend` и FBX.
2. Manifest записан: SHA256, габариты, треугольники по LOD, материалы.
3. Импорт в Unity через Builder прошёл, лог в `artifacts/reports/`, проверка габаритов и осей — PASS.
4. Префаб: корень identity, лицевая сторона +Z, pivot по разделу 3, коллайдеры на месте, слой верный.
5. Рендеры: Blender (ДО/ПОСЛЕ, если это правка) и **Unity** — фиксированные ракурсы, страница в `artifacts/visual-review/<kit>/`.
6. Для автомобиля — геометрическая приёмка G01–G08 из `asset-standard.md`.
7. Документ набора (`docs/<kit>.md`) обновлён: состав, размеры, как пересобрать, ограничения.

Статусы: PASS / FAIL / NOT_RUN / BLOCKED. Рендер Blender или веб-просмотр **не доказывают** корректность в Unity.

## 11. Правила для агентов
- Ассет меняет **один** исполнитель. Проверяет **другой**: смотрит рендеры и отчёт, не доверяя словам исполнителя.
- Исполнитель получает путь к актуальному исходнику, список дефектов, разрешённые файлы и критерии приёмки. Вся история проекта ему не нужна (порядок работы — `model-iteration.md`).
- Не перезаписывать `.blend`, в который человек вносил ручные правки: сначала проверить время изменения, при сомнении — спросить.
- Не прятать дефект сменой ракурса, двусторонним материалом или исключением объекта из рендера.
- Кодовый агент не правит `.blend` и FBX ради прохождения теста.
