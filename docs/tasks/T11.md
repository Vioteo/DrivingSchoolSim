# T11 — Схема RoadGraph v2 и миграция данных (RoadGraph v2 & Migration)

- **Требования:** R07 (единый дорожный граф), R15 (доказуемость).
- **Критерий приёмки:** A07 (graph schema v2 & migration).
- **ADR:** ADR-002 (версионирование данных), ADR-003 (единый roadgraph).

## 1. Конкретный результат и зависимости

Разработать расширенный формат дорожного графа `WorldDocumentV2` и детерминированный мигратор `WorldMigrationV1ToV2`:
- Поддержка криволинейных участков дорог через контрольные точки Безье (`CubicCurveDefinition`).
- Строгая спецификация полос движения:
  - Разделение направлений (полосы попутного направления `index > 0`, встречного `index < 0`).
  - Ширина полосы `widthM`, расчетная осевая линия `centerlinePoints`.
  - Явные связи преемственности полос на перекрестках (`LaneConnection` с углами съезда и конфликтными группами).
- Дорожные регуляторные элементы:
  - Стоп-линии (`StopLine` с привязкой к полосе и координате `distanceAlongLane`).
  - Пешеходные переходы (`PedestrianCrossing`).
  - Светофорные группы (`TrafficSignalAttachment`).
- Автоматическая миграция документа v1: прямые сегменты v1 корректно преобразуются в эквивалентные сегменты v2.

## 2. Разрешённая область изменений

- `Assets/DrivingSchool/Code/Contracts/WorldDocumentV2.cs` (новые DTO)
- `Assets/DrivingSchool/Code/World/WorldMigration.cs` (мигратор v1 → v2)
- `Assets/DrivingSchool/Code/Tests/WorldMigrationTests.cs` (тесты миграции)
- Файловый бюджет: 2 production files + 1 test file.

## 3. Точные входы, выходы и контракты

- **Контракт мигратора:**
  ```csharp
  public static class WorldMigration
  {
      public static WorldDocumentV2 MigrateV1ToV2(WorldDocument v1);
      public static bool CanMigrate(int sourceSchemaVersion);
  }
  ```
- **Вход:** Валидный `WorldDocument` v1 (например, `Assets/StreamingAssets/Examples/world.json`).
- **Выход:** `WorldDocumentV2` со `schemaVersion = 2`, где все 16 полос v1 сохранили свои топологические связи и получили вычисленные осевые линии.

## 4. Примеры данных и ожидаемого поведения

- Документ v1 с сегментом длиной 100 м между узлами `(0, 0, 0)` и `(0, 0, 100)`:
  - В v2 формируется сегмент с прямой кривой Безье `startTangent = (0, 0, 33.3)`, `endTangent = (0, 0, 66.7)`.
  - Полосы получают координаты центральной линии с дискретизацией не более 2 м.
  - Поле `schemaVersion` становится строго `2`.

## 5. Отрицательные сценарии

- **Неподдерживаемая версия схемы (например, 99):** Метод `CanMigrate(99)` возвращает `false`, а вызов `Migrate` выбрасывает `NotSupportedException` с четким указанием неподдерживаемой версии.
- **Висячие ссылки в v1 (broken successor):** Если в исходном v1 указан несуществующий successor, валидатор перед миграцией обязан отклонить документ с `InvalidDataException`, исключая распространение скрытой порчи данных в v2.
- **Совпадающие координаты узлов:** Сегмент нулевой длины (`fromNode == toNode`) отклоняется с ошибкой валидации геометрии.

- Структуры `WorldDocumentV2` объявлены в `DS.Contracts`.
- Миграция примера `world.json` v1 в v2 проходит без потерь узлов и полос.
- Написаны тесты, доказывающие эквивалентность топологии до и после миграции.
