# T35 — Менеджер трафика и Unity-адаптер (Traffic Manager & Presentation)

- **Требования:** R09, R14.
- **Критерий приёмки:** A11.
- **ADR:** ADR-001, ADR-012. Дизайн: [city.md](../city.md#менеджер-трафика-t35).
- **Зависит от:** T16, T30, T31, T33 (T34 — для поведения в 2+2).

## 1. Конкретный результат и зависимости

- Pure C# `TrafficSimulation`: список агентов, маршруты A* по графу, появление и исчезновение в `SpawnPoint` вне поля зрения игрока (150–250 м), шаг решений 10 Гц, seed.
- Плотность и профили водителей — данные `Assets/DrivingSchool/Data/City/traffic-profile.json`. **Первый профиль: до 8 машин на район.**
- Unity-адаптер `TrafficView`: пул префабов, kinematic Rigidbody + коллайдер, интерполяция позы, поворот колёс по кривизне, поворотники и стоп-сигналы.
- Столкновение с игроком: агент останавливается, включает аварийку, публикуется событие для правил.

## 2. Разрешённая область изменений

- `Assets/DrivingSchool/Code/Simulation/Traffic/TrafficSimulation.cs`
- `Assets/DrivingSchool/Code/Presentation/TrafficView.cs`
- `Assets/DrivingSchool/Data/City/traffic-profile.json`
- `Assets/DrivingSchool/Code/Tests/TrafficSimulationTests.cs`
- Файловый бюджет: 2 production files + данные + 1 test file.

## 3. Точные входы, выходы и контракты

- Симуляция не знает про GameObject; адаптер не принимает решений.
- Один и тот же seed и input trace игрока → одинаковая история агентов (сравнение хеша состояний).

## 4. Примеры данных и ожидаемого поведения

- 10 минут симуляции района v0 с 8 машинами: нет пересечений габаритов, нет агентов, «застрявших» дольше порога, число агентов не превышает профиль.

## 5. Отрицательные сценарии

- Точка появления занята → агент не появляется в ней (нет наложения).
- Агент не появляется и не исчезает в поле зрения игрока.
- Маршрута нет → агент не создаётся, в лог причина.


- 10-минутный прогон без нарушений инвариантов; детерминизм подтверждён тестом; видео Play Mode приложено.
