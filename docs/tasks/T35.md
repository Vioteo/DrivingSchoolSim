# T35 — Диспетчер трафика: единый узел управления (Traffic Director)

- **Требования:** R06, R09, R14.
- **Критерий приёмки:** A11.
- **ADR:** ADR-001, ADR-012, ADR-014. Дизайн: [city.md](../city.md#диспетчер-трафика).
- **Зависит от:** T16, T30, T31, T32. Повторяемая карточка: T33, T34, T36 подключаются к диспетчеру своими итерациями.

## 1. Конкретный результат и зависимости

Итерация 1 — каркас, с которым в районе v0 ездят машины:
- Pure C# `TrafficDirector`:
  - реестр участников: машины ИИ, пешеходы (пока пусто), игрок как внешний участник только для чтения;
  - фиксированный порядок тика (city.md, «Что делает диспетчер за один тик»);
  - владеет всеми `SignalController` района (T32) и тикает их;
  - строит один неизменяемый снимок мира на тик и передаёт его модулям поведения; результат не зависит от порядка обхода агентов;
  - маршруты A* по графу; появление и исчезновение в `SpawnPoint` вне поля зрения игрока и только в загруженных чанках;
  - уровни детализации: ближняя зона (полное поведение), фоновая (только IDM, 1–2 Гц, без объектов в сцене); фазы светофоров вне загруженной области вычисляются из плана по времени;
  - seed; публикация снимка для представления, правил и отладки.
- Плотность и профили водителей — `Assets/DrivingSchool/Data/City/traffic-profile.json`. **Первый профиль: до 8 машин на район.**
- Unity `TrafficDirectorHost`: единственный MonoBehaviour, который вызывает `Tick` в FixedUpdate, передаёт состояние игрока, применяет снимок к `TrafficView` (пул машин, kinematic Rigidbody, интерполяция, колёса, поворотники и стоп-сигналы) и к `TrafficSignalView`. Сообщает диспетчеру о контактах с игроком.

Следующие итерации (отдельными карточками, в диспетчер): таблица резервов зон (T33), перестроение и объезд (T34), пешеходы (T36), связь с загрузкой чанков (T12).

## Реализация, итерация 1 (24.09.2026)

Сделано: `TrafficDirector` (реестр, порядок тика, светофоры, снимок, маршруты по графу со случайным выбором на развилках, появление вне взгляда игрока и только в загруженных чанках, исчезновение на краю района, уровни детализации, контакт → аварийка), `TrafficSnapshot`, `TrafficDirectorHost` + `TrafficVehicleView` (Unity). ## 3. Точные входы, выходы и контракты

```csharp
public sealed class TrafficDirector
{
    public TrafficDirector(WorldDocumentV2 graph, TrafficProfile profile, int seed);
    public void SetPlayer(PlayerSample sample);        // поза, скорость, фары/поворотники из VehicleState
    public void OnChunkReady(int cx, int cz);          // T12; до интеграции — весь район загружен
    public void OnChunkUnloaded(int cx, int cz);
    public void ReportContact(string agentId, string otherId);
    public void Tick(long tick, double simSeconds);
    public TrafficSnapshot Snapshot { get; }           // неизменяемый, для представления, правил и отладки
}
```

- Диспетчер не знает про GameObject; `TrafficDirectorHost` не принимает решений о движении.
- Правила ПДД (T18) берут сигналы, участников и резервы только из `Snapshot`.

## 4. Примеры данных и ожидаемого поведения

- 10 минут симуляции района v0 с 8 машинами: нет пересечений габаритов, нет агентов, стоящих дольше порога без причины, число агентов не превышает профиль, все машины останавливаются на красный.
- Повторный прогон с тем же seed и тем же trace игрока → тот же хеш снимков.
- Перестановка порядка агентов в реестре не меняет хеш снимков.

## 5. Отрицательные сценарии

- Точка появления занята или в поле зрения игрока → агент не появляется.
- Чанк не загружен → агент в нём не появляется в ближней зоне.
- Маршрута нет → агент не создаётся, в лог причина.
- Пауза: `Tick` не вызывается, фазы светофоров и агенты стоят.
- Контакт с игроком → агент стоит с аварийкой, в снимке есть событие контакта.
