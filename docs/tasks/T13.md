# T13 — Перенос начала координат (Floating Origin Service)

- **Требования:** R06 (мир 10 × 10 км без потери точности float), R15 (доказуемость).
- **Критерий приёмки:** A08 (large world & floating origin).
- **ADR:** ADR-004 (канонические double и floating origin).

## 1. Конкретный результат и зависимости

Создать сервис плавающего начала координат `FloatingOriginService`:
- Устраняет дрожание физики (jitter) и артефакты z-fighting в мире 10 × 10 км из-за ограниченной точности 32-битных чисел с плавающей точкой (single precision float).
- Все канонические позиции мира хранятся в `double` (SI метры).
- Локальная сцена Unity центрируется вокруг игрока: `unityPosition = (Vector3)(worldPositionDouble - currentOriginDouble)`.
- Пороговый сдвиг: при удалении фокуса от текущего начала сцены более чем на 500 м выполняется атомарный перенос:
  - Смещение позиций всех зарегистрированных активных объектов (`Transform`, `Rigidbody.position`).
  - Сохранение импульсов, линейных и угловых скоростей `Rigidbody.linearVelocity` без обнуления.
  - Сохранение положения частиц (particle systems) и виртуальных камер.
  - В VR: перенос origin не сбивает пользовательскую калибровку недавнего центрирования (recenter pose).

## 3. Точные входы, выходы и контракты

- **Контракт интерфейса:**
  ```csharp
  public class FloatingOriginService : MonoBehaviour
  {
      public Vector3d CurrentOrigin { get; }
      public float ShiftThresholdDistance { get; set; } = 500f;
      public event System.Action<Vector3> OnOriginShifted;
      public Vector3 ToUnitySpace(double wx, double wy, double wz);
      public Vector3d ToWorldSpace(Vector3 unityLocal);
      public void Register(IFloatingOriginParticipant participant);
      public void Unregister(IFloatingOriginParticipant participant);
  }
  ```
- **Входы:** Координаты игрока в double, регистрация движущихся и статических объектов.
- **Выходы:** Событие `OnOriginShifted(Vector3 delta)` на границе шага `FixedUpdate`.

## 4. Примеры данных и ожидаемого поведения

- Машина движется по шоссе на восток:
  - Каноническая координата: `x = 4500.0`, текущий origin: `(4000.0, 0, 0)`. Позиция в Unity: `(500.0, 0, 0)`.
  - Машина достигает `x = 4505.0`: превышен порог 500 м.
  - Origin смещается в `(4505.0, 0, 0)` (`delta = (505.0, 0, 0)`).
  - Позиция машины в Unity становится `(0.0, 0, 0)`.
  - Все объекты сцены получают вычитание вектора `delta`.
  - Скорость машины 25 м/с сохраняется без скачка ускорения.

## 5. Отрицательные сценарии

- **Скачок скорости при сдвиге Rigidbody:** Если двигать Transform без обновления `Rigidbody.position`, физический движок посчитает мгновенное перемещение за один кадр огромной скоростью `delta / dt`. Сдвиг обязан производиться через `Rigidbody.position -= delta` в контексте Physics Tick.
- **Дрожание дорожного графа:** Канонический граф и координаты нарушений ПДД в `RuleEvent` хранят неизменяемые double-позиции; они никогда не модифицируются сдвигом origin.
- **Сдвиг во время пересечения перекрестка:** Не должен приводить к ложным срабатываниям датчиков столкновений или правил проезда перекрестка.
