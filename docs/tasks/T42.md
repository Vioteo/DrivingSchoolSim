# T42 — Переход с G27 на G29 + Driving Force Shifter

- **Требования:** R02 (ввод), R03 (FFB), R15 (доказуемость).
- **Критерий приёмки:** A04 (input), A05 (FFB).
- **Основание:** 24.09.2026 владелец уточнил железо: Logitech G29 + Driving Force Shifter, а не G27. Решение записано в CLAUDE.md и requirements.md R02.

## 1. Конкретный результат и зависимости

Код и документы перестают предполагать G27:
- адаптер руля и его тесты называются по назначению (`LogitechWheelAdapter` или по модели G29 — решить в начале задачи), имена тестов обновлены;
- раскладка осей и кнопок G29 и шифтера снята с реального устройства (live axes в калибровке) и записана как данные, а не угадана по имени устройства (architecture.md §«Ввод»);
- кнопки меню по `docs/ui-settings.md` §6 (крестовина, ✕, ○, лепестки, OPTIONS) привязаны через Input System actions;
- FFB-бэкенд для G29 выбран с обоснованием лицензии и доставки DLL (architecture.md), до выбора — только mock.

Зависимость: T04 (keyboard input) как образец `IInputSource`; T05 (калибровка) переименовать и перепроверить под G29.

## 3. Входы, выходы, контракты

- Выход — тот же `DriverCommand` (`IInputSource`): руль −1…1, педали 0…1, `requestedGear` −1/0/1…6. Контракты не меняются.
- Шифтер: 6 передач + R; R включается нажатием рычага вниз (как у G27 — проверить на устройстве).

## 4. Отрицательные сценарии

- Руль подключён без шифтера → H-передачи недоступны, UI показывает это; лепестки не подменяют H-паттерн молча.
- Отключение руля или шифтера в поездке → газ 0, пауза (A04).
- Неизвестное устройство с похожим именем → не применять раскладку G29 автоматически.

## 5. Проверка и доказательства

- EditMode: переименованные тесты адаптера проходят; добавлен тест «без шифтера передача = N».
- Аппаратно: протокол калибровки на реальном G29 + шифтере (оси, кнопки, 6+R) в `artifacts/reports/`.
- `grep -rn G27` по `Assets/` и `tools/` пуст, кроме истории миграции.

## 6. Условия завершения

Код, тесты, генератор UI и документы используют G29; раскладка кнопок подтверждена на устройстве; статусы по формату CLAUDE.md.

## 7. Ход работы

- 28.09.2026 (ветка `feat/T42-wheel-ccd`): руль подключён к машине поверх клавиатуры — `WheelProfile` (раскладка как данные, `wheel-g29.json`, по умолчанию как в City Car Driving), `WheelDevice` (поиск по VID/PID, контролы по путям), `WheelInputSource` (оси, кнопки, H-шифтер, блокировка P на АКПП), выбор в «Устройство ввода», подсказки уроков для руля (`LessonControls`), пауза OPTIONS, камера SHARE, взгляд крестовиной, оверлей F11. Раскладка на устройстве **ещё не подтверждена** (номера кнопок — по известной схеме G29, оси — `stick/x`, `z`, `rz`, `stick/y`); проверить по F11 и записать протокол. Переименование `LogitechG27Adapter` и FFB — не сделаны.
- 28.09.2026, после первой проверки владельцем на G29: руль поворачивал, но машина не заводилась кнопками, меню рулём не управлялось. Найдено: стандартные действия UI Input System навигируют по `<Joystick>/stick` — у G29 это руль и сцепление, отпущенная педаль держала «стрелку». Исправлено (`WheelMenuBridge`), меню — крестовина/✕/○/лепестки (`MenuInput`). Оси теперь калибруются захватом по движению (`ControlsSetupPanel`, калибровка), кнопки и клавиши — переназначением нажатием (`KeyboardProfile`, `keyboard.json`). Почему не сработали кнопки в поездке, по факту не установлено (Editor.log недоступен): вероятнее всего, сцепление не на `stick/y` → стартер на МКПП не крутил. Факты с устройства пишутся в `Logs/wheel-diagnostics.txt`.
