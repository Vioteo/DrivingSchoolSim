# Настройка Claude для DrivingSchoolSim

## 1. Что уже положено в проект

Файлы агентов лежат в `docs/claude-agents/`: папку `.claude` удалённо записать нельзя. **Скопируйте их вручную в `.claude/agents/`** в корне проекта (создайте папку). После этого агенты станут доступны.

| Файл | Зачем |
|---|---|
| `CLAUDE.md` (корень) | Главный контекст. Claude и все агенты читают его автоматически при работе с папкой: стек, структура, запреты, как проверять, приоритеты. **Держать актуальным** — это самое полезное, что можно настроить. |
| `.claude/agents/unity-implementer.md` | Исполнитель задач в C#/Unity (Sonnet — быстро и дёшево). |
| `.claude/agents/vehicle-physics.md` | Физика авто, КПП, шины, FFB (Opus). |
| `.claude/agents/pdd-rules-expert.md` | ПДД, методика экзамена ГИБДД, ГОСТ; выдаёт правила как JSON-данные (Opus). |
| `.claude/agents/reviewer.md` | Независимая проверка результата, ничего не правит (Opus). |

## 2. Текст для «Инструкций проекта» в Claude
Скопируйте в настройки проекта (Project instructions):

```
Я разрабатываю DrivingSchoolSim — учебный симулятор вождения по ПДД РФ на Unity 6000.3 (URP), эталон — City Car Driving. Папка проекта: C:\Users\AVSok\Projects\unity-driing\DrivingSchoolSim.

Перед любой работой с кодом прочитай CLAUDE.md в корне проекта и следуй ему. Актуальное состояние — docs/audit-2026-09-23.md.

Как со мной работать:
- Отвечай по-русски. Коротко и по делу, без пересказа того, что я и так вижу.
- Большие задачи дроби на карточки (docs/tasks) и выполняй по одной; после каждой — проверка агентом reviewer.
- Не говори «готово/работает», если это не проверено запуском: пиши PASS / FAIL / NOT_RUN с командой и логом.
- Нормы ПДД и методики ГИБДД — только со ссылкой на источник и редакцию. Не выдумывай.
- Если нужно архитектурное решение, которого нет в docs, — спроси меня с вариантами.
```

## 3. Что загрузить в «Знания» проекта
Загружать стоит **стабильные** документы, а не код (код меняется, и загруженная копия устареет — Claude читает его из папки напрямую):
- `docs/audit-2026-09-23.md`, `docs/requirements.md`, `docs/architecture.md`, `docs/adr.md`, `docs/data-formats.md`.
- Схема автодрома (`schema.jpg`), когда будет — схема города/маршрутов.
- Первоисточники по ПДД: текст ПДД (Постановление № 1090) и Административный регламент экзамена (приказ МВД № 80) в действующей редакции — PDF с consultant.ru/garant.ru. Это резко повысит точность правил.
- Описание целевого автомобиля и ощущений от CCD: что нравится/не нравится (можно своими словами).

Не загружать: логи, `.agents/`, рендеры, `ORIGINAL_REQUEST.md` (устарел).

## 4. Как делить задачи между агентами
Типовой цикл одной задачи:
1. **Я (главный Claude)** — беру пункт из плана, формулирую карточку: цель, файлы, запреты, критерий приёмки, команда проверки.
2. **Исполнитель** по профилю: `unity-implementer`, `vehicle-physics` или `pdd-rules-expert`.
3. **reviewer** — независимая проверка. При «ДОРАБОТАТЬ» — обратно исполнителю.
4. Обновить `CLAUDE.md` / `docs/current-state` если изменилось что-то важное.

Параллелить можно только задачи, которые не трогают одни и те же файлы (например, pdd-rules-expert готовит таблицу ошибок, пока vehicle-physics делает сцепление). С git это безопаснее: каждый агент — в своей ветке/worktree.

Просить так: «Возьми задачу X, делегируй исполнителю, потом ревьюеру» — или просто «сделай следующий пункт плана».

## 5. Что сделать вам вручную (важно)
1. **Git.** `git init`, Git LFS для `*.fbx *.blend *.png *.glb`, первый коммит. Без этого агенты не могут безопасно работать параллельно и откатываться.
2. **OneDrive.** Перенести проект в папку вне OneDrive (например `C:\dev\DrivingSchoolSim`) или хотя бы исключить `Library/`. После переноса поправить путь в инструкциях проекта.
3. **Удалить или архивировать `.agents/`, `*_Backup`, логи в корне** — они засоряют поиск и сбивают агентов старыми выводами.
4. **Держать компьютер с Unity доступным**, когда нужен запуск тестов: агенты запускают Unity через ваш компьютер.
