# Порядок доработки моделей

Пожелание заказчика от 19.09.2026: основной способ моделирования — скрипты Blender с оценкой реальных рендеров отдельных частей с разных ракурсов. Постоянное управление интерфейсом через компьютер не требуется.

## Небольшое задание исполнителю

Каждый агент получает только путь последнего исходника, конкретные дефекты, разрешённые файлы и критерии завершения. Один исполнитель изменяет конкретную модель; координатор независимо смотрит результат и проверяет экспорт. Полная история симулятора для ремонта геометрии не нужна.

1. Проверить время изменения исходника; сохранить его без перезаписи. Не запускать старый генератор поверх пользовательских правок.
2. Диагностировать геометрию, нормали, материалы и модификаторы. Отделить отсутствие поверхности от прозрачного материала или неверной ориентации граней.
3. Получить несколько небольших рендеров ДО с фиксированными камерами. Для кузова обязательны фронтальный, нижний и косой виды; для салона — водительское место и проблемный узел.
4. Исправить геометрию воспроизводимым Python-скриптом. Сохранить новую версию `.blend`. Не прятать дефект сменой камеры, двусторонним материалом или исключением проблемного объекта из рендера.
5. Отрендерить ПОСЛЕ теми же камерами и светом. Открыть изображения, записать обнаруженные проблемы и повторить исправление, если они остались. Для непонятного участка повысить разрешение только его кадра.
6. Проверить, что исправление не перекрыло арки, окна, педали и независимые детали. Геометрия с технологическими отверстиями не обязана быть единой водонепроницаемой сеткой; вновь добавленные сплошные панели должны иметь толщину и согласованные нормали.
7. Экспортировать версионные FBX/GLB, повторно импортировать, сверить размеры, необходимые привязки и материалы. Blender reimport не заменяет проверку в Unity.
8. Приложить короткий отчёт и страницу ДО/ПОСЛЕ. Обозначить точный объём PASS; оставшиеся дефекты сохранять как открытые.

## Текущая ограниченная задача

- Исходник: `ArtSource/DS_Sedan_A_reviewed.blend`.
- Дефекты: видимая пустота спереди под капотом; просветы через нижнюю часть кузова.
- Новая версия: `ArtSource/DS_Sedan_A_closed_shell.blend`.
- Скрипт ремонта: `tools/repair_shell.py`.
- Рендеры: `artifacts/visual-review/shell-repair/`.
- Проверка обменных форматов: `tools/export_sedan_review.py`.
- Приёмка: закрыты непредусмотренные просветы спереди и снизу; колёса и педали остаются отдельными и видимыми; исходный файл сохранён; результат проверен по изображениям. Ход подвески, физика, зеркала Unity и VR не входят в эту приёмку.

Команда проверки экспорта (из корня DrivingSchoolSim, после подготовки новой версии):

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.0\blender.exe' -b ArtSource/DS_Sedan_A_closed_shell.blend --python tools/export_sedan_review.py
```

Отчёт `artifacts/reports/shell-export-check.json` содержит фактические размеры, SHA-256 файлов и результат проверки. Он появляется только после запуска проверки; этот документ сам по себе не подтверждает её прохождение.
